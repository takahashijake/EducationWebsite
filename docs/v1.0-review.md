# V1.0 review: Stacks, Queues, and applied problem solving

## Scope

The permanent `stacks-queues` topic is published at `/lessons/stacks-queues` with advisory Arrays and Strings, Linked Lists, and Big O prerequisites. The existing `Lesson`, `LessonDemonstration`, `CodeLab`, Pyodide Worker, learning catalog, deterministic adaptive generator, five-question session, Learning Insights, and browser-local V1 stores are reused. No new runtime dependency, backend execution endpoint, or storage schema is introduced. Version is 1.0.0.

The lesson teaches LIFO/FIFO, push/pop/peek, enqueue/dequeue/front/rear, empty underflow, linked top/head/tail transitions, equal values versus node identity, representation and complexity tradeoffs, and transfer to balanced delimiters and task processing. Three authored checks and worked queue reference transitions accompany the player and sections. The player uses `None` for empty removal/inspection; individual Python contracts state the same choice. Other APIs may raise on empty access.

## Interactive engine contract

`src/lib/stack-queue-steps.ts` is pure and independent of React. `generateStructureSteps(kind, operations)` yields an initial snapshot and one snapshot per operation, with copied active nodes `{id,value,next}`, `head`, `tail`, reachable `order`, operation/result, and invariant narration. Node IDs are logical identities, stable across steps and never reused after clear. They are not addresses. `structureOrder` rejects duplicate IDs, dangling `next` or `head`, cycles, and unreachable active nodes; the generator also verifies tail is the last reachable node. Empty structures have both endpoints null. Stack top uses head; its tail denotes the bottom only for validation. Queue enqueue updates old tail.next and tail, and sets both endpoints for an empty queue. Removing a singleton sets both endpoints null. Review rewinds immutable snapshots instead of reversing pointer changes.

Input is bounded to 12 operations, 10 active nodes, and 12 characters per inserted value. Invalid operations/values throw from the pure engine and display guidance in the UI. Scenarios include LIFO, FIFO, repeated values, empty removal, and singleton transitions; the learner can compose a short sequence. Native buttons/selects, explicit pointer labels, textual node information, narration in a live region, and a wrapping layout support keyboard and narrow screens. The player traces authored operations, not submitted Python.

## Python Code Labs

Six browser exercises use public checks, progressive hints, reflections, and checked references:

| Lab               | Contract                                                                                                        |
| ----------------- | --------------------------------------------------------------------------------------------------------------- |
| `sq-stack-sim`    | `simulate_stack(operations)` returns pop/peek results in operation order; empty access returns `None`.          |
| `sq-queue-sim`    | `simulate_queue(operations)` returns dequeue/front results in FIFO order; empty access returns `None`.          |
| `sq-linked-stack` | `LinkedStack` maintains `top`; push creates a node and pop/peek return values or `None`.                        |
| `sq-linked-queue` | `LinkedQueue` maintains `head`/`tail`, including empty and singleton boundaries.                                |
| `sq-delimiters`   | `balanced_delimiters(text)` checks nesting of `()[]{}`; ignores all non-bracket characters.                     |
| `sq-tasks`        | `process_tasks(arrivals, limit)` returns new completed/remaining lists in FIFO order without mutating arrivals. |

Each starter contains a meaningful defect. Public cases cover empty, singleton, duplicate/order, mismatched nesting, early closers, preserved node identity, and endpoint updates. References are executed against every public case in authoring tests. The existing Code Lab records attempts and drafts separately and withholds independent positive evidence after hints or reference disclosure. The Worker, deadline, and output bounds remain unchanged. Public tests are advisory and cannot prove general correctness or mastery.

## Adaptive learning and compatibility

Six new permanent skills cover stack LIFO, stack boundaries, queue FIFO, queue references, representation cost, and applied transfer. Each has two independently authored focused retrieval questions and two deterministic adaptive families, totaling 12 retrieval questions and 12 families. Three lesson checks and six Python activities map to relevant skills. Generated variants retain one family activity identity and revision 1, so changing a seed does not inflate independent activity counts. Existing remediation, session selection, review links, and evidence rules apply. Wrong answers point to the published lesson. Existing V1 evidence, workspace drafts, completion, project progress, and adaptive session records retain their formats and IDs. Reading completion, assisted success, independent success, and mastery remain distinct.

Python list indexing is O(1). End append/pop are amortized O(1); a resize may make an individual append O(n). `list.pop(0)` shifts entries and costs O(n). `collections.deque` normally fits FIFO work with O(1) end operations. Maintained linked head/tail yield O(1) enqueue/dequeue but add per-node reference/object overhead and poorer locality. These are operation costs, not measurements of the browser diagrams.

## Security and limits

No new package, server runner, authentication, database, or external model API is used. Learner Python still executes in a disposable Pyodide browser Worker with existing source, deadline, and output limits. It is not a hostile-code security boundary; the Python JavaScript bridge can access same-origin browser capabilities. Run only trusted Python on an origin with sensitive data. The authored adaptive generator does not evaluate user text as code. Existing Rubber Duck / CodeAnalyzer findings must be compared with the V0.8 baseline before classifying regressions; scanner settings were not weakened.
