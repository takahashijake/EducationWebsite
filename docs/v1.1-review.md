## Pure traversal engine

`src/lib/graph-steps.ts` validates 1–9 distinct A–J vertices and at most 18 edges. Endpoints must exist; duplicate directed edges and duplicate undirected pairs, including reversed duplicates, are rejected. Self-loops are legal and examined without re-discovery. Undirected edges populate both neighbor lists. All neighbor lists are sorted alphabetically before traversal. The player and Python lab contracts follow the same order. A single start visits only its reachable set.

BFS marks on enqueue, uses a FIFO queue, and records a predecessor and integer edge distance on first discovery. This prevents duplicate enqueue and preserves minimum-edge paths under equal unit edge costs. A target path is reconstructed from predecessors; alphabetical neighbors break equal-length ties. Weighted shortest paths are outside this guarantee. DFS stores explicit `{vertex, nextNeighbor}` frames, marks on descent, explores one neighbor before siblings, and emits backtracking snapshots. This matches recursive DFS discovery order. Both algorithms skip already discovered vertices, including cycle and self-loop edges. Every snapshot copies frontier, frames, parents, distances, order, and examined edge so review does not mutate earlier states.

Six scenarios cover a chain, branch, cycle, disconnected graph, directed graph, and two equally short routes. The accessible player includes a stable-position SVG diagram plus textual adjacency and vertex state, a queue or frame panel, narration, step review, reset, start and target controls, and bounded graph composition. It asks learners to predict the next *discovered* vertex before revealing it. Prediction feedback is ephemeral and awards no learning evidence. The player traces its own authored graph operations, not learner Python.

## Complexity, security, and limitations

For already ordered adjacency lists, full BFS or DFS takes O(V + E) time and O(V) auxiliary traversal space, with O(V + E) graph storage. Sorting unsorted neighbors adds cost. A matrix uses O(V²) storage, O(1) specific-edge lookup, and O(V²) full-row traversal time. The diagram is a bounded conceptual model; it does not measure browser performance or trace arbitrary Python. Public checks are formative, not secure grading. Browser Pyodide is not a hostile-code isolation boundary; its JavaScript bridge can access same-origin browser capabilities. Use only trusted code on origins with sensitive data. No server-side learner-code execution was introduced.
