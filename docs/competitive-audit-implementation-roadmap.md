# Remaining competitive-audit implementation roadmap

V1.7 addresses authored misconception recovery for one skill, a contextual lesson next step, returning-learner signal context, and planned-topic routing. The October audit remains the product evidence base. Release order is indicative and subject to human learning and accessibility review.

| Finding / current status | Why and proposed implementation | Dependencies; effort; release; acceptance |
|---|---|---|
| Unified predict → explain → implement → transfer; players and code labs are separate | A learner can pass one representation without transferring the invariant. Pair one graph or DP prediction with explanation, runnable Python, and a novel case. Label the player as authored, not a trace of learner code. | Educator rubric and one matching lab; **L**, **V1.8 first**. Accept: same invariant across steps, multiple legitimate code solutions, delayed unfamiliar case and no false mastery claim. |
| Portable browser-local progress; no export/import | Device/origin changes lose local work. Add bounded versioned JSON export/import with preview and explicit merge/replace, using existing V1 validators. | Storage schema review and privacy UX; **M**, V1.8/1.9. Accept: corrupt/oversized input rejected, round-trip across origins, no V1 ID changes. |
| Independent projects; one guided five-stage project | Transfer and creativity need more than one scaffold. Add one open-ended cross-topic project with a human-readable rubric and advisory local checks. | Curriculum and rubric review; **L**, V1.9. Accept: at least two valid approaches and external evaluation of explanation and boundary testing. |
| Adaptive diversity validation; authored families but template overfitting unmeasured | Add misconception/transfer-distance rubric and adversarial seed checks, then pilot novel-question probes. | Authoring rubric and educator review; **M**, V1.8. Accept: every new family has invariant, distractor rationale, boundaries and seed coverage. |
| Long-lesson cognitive load; content-rich pages | Add section milestones and resume anchors after learner testing; preserve all content and semantic headings. | Novice think-aloud study; **M**, V1.9. Accept: improved resume/comprehension tasks without keyboard traps. |
| Public code tests; clearly formative but easy to over-read | Add optional boundary-and-explain prompts after pass, preserving completion semantics. | Exercise authors; **M**, V1.9. Accept: public pass is never called mastery; novel boundary checks can fail independently. |
| C++ first download; approximately 95 MB | Improve stage/retry messaging and offer a lightweight conceptual path before compiler use. | Performance measurements on real networks; **S/M**, V1.8. Accept: no misleading progress percentage, no CSP relaxation, measured first-run completion. |
| Assistive-technology evidence; automated keyboard/mobile checks exist | Test representative journeys with screen readers, reduced motion and keyboard; fix confirmed blockers. | Testers/devices; **M**, ongoing. Accept: reproducible issue log, WCAG mapping and retest on desktop/mobile. |

**Best next implementation: V1.8 linked invariant transfer.** Start with one published graph or DP concept. Reuse pure step generators and Python labs; do not build arbitrary code tracing or a backend. Evaluate a delayed unfamiliar problem and an explanation rubric before broadening the pattern.
