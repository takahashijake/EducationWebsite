Related links return to Graphs and Big O.

## Reference graph, heap, and trace contracts

`weighted-graph-steps.ts` is pure TypeScript and separate from the V1.1 unweighted BFS/DFS representation. It accepts 1–9 distinct A–I vertices, at most 18 edges, directed or undirected, and finite safe integer weights from 0 through 999. It rejects unknown endpoints, duplicate directed pairs, reversed duplicate undirected pairs, invalid weights, and invalid source/destination labels. A self-loop is legal; it cannot improve its own already settled source. An undirected edge populates both adjacency lists. Labels and outgoing neighbors are sorted alphabetically. The UI composer uses the same validation before accepting an edge, with an explicit error rather than a render crash.

A binary heap orders `(distance, vertex label, insertion sequence)`. Each strict improvement pushes a fresh entry. Old entries remain in the heap and are skipped on removal if their vertex is settled or their distance differs from the current estimate. The player shows the removed minimum separately from the remaining heap so it never presents a removed item as queued. It shows an attempted edge candidate and a success or failure for every outgoing edge. Trace phases are initial, select, settle, relax, stale, and complete. Every snapshot owns copied distances, predecessors, settled/unsettled lists, sorted heap contents, selected entry, current edge, route, cost, and narration. Nested collections and snapshots are frozen. The queue is bounded to 37 entries (one source plus at most two adjacency directions per input edge), and trace generation is bounded to 128 steps; the graph limits imply a smaller worst case (at most one initial, two steps per vertex, one relaxation per adjacency entry, one stale step per superseded entry, and one final step). All trace computation stays client-side.

## Invariant and tie policy

Only a valid minimum heap entry settles a vertex. With nonnegative edge weights, a route through another unsettled vertex cannot later lower that minimum: its prefix is at least the selected distance and its remaining edges cannot subtract cost. The algorithm never assumes that an initial tentative distance is final. A negative edge would break this proof, so input validation rejects it and the lesson points to Bellman-Ford for graphs with negative edges and no reachable negative cycle. Bellman-Ford is a comparison, not an implemented feature.

Relaxation changes distance and predecessor only for a **strict** improvement. Equal-cost alternatives retain the first discovered parent. Alphabetical heap and neighbor ordering make that parent deterministic. This avoids parent cycles even with zero-weight cycles. The source has cost 0 and null predecessor; unreachable vertices remain null/infinity. A destination path follows predecessors backward, reverses once, and is guarded against malformed cycles. The displayed current path can be tentative until its destination is settled; the final path and cost come from the final trace snapshot. Optional destination selection changes route reporting, not the all-vertex algorithm.

## Accessibility, security, and limitations

The player offers labeled keyboard controls, live narration, textual adjacency and state tables, visible weights, explicit outcomes, focus rings, and mobile overflow containment. Reciprocal directed edges have separate curved lines; self-loop labels are offset. Color supports but does not carry essential state alone. The player has no timed animation, so reduced-motion preferences require no alternate playback. Automated desktop/mobile Chromium checks do not replace human screen-reader and teaching review.

The engine runs validated bounded data and never evaluates learner source. Python still runs in the browser Pyodide Worker with existing deadlines and output bounds, not on the application server. The Python JavaScript bridge can reach same-origin browser capabilities; the Worker is not a hostile-code isolation boundary. No authentication, database, hosted inference, paid dependency, or new backend is added. The diagram is a small teaching model and is not a general large-graph editor. Complexity claims concern the underlying heap algorithm, not snapshot rendering or adjacency sorting.
