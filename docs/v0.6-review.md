## Instructional architecture

`src/content/dsa-lessons.ts` contains the complete lessons, three knowledge checks and a prediction question in each. Arrays covers zero-based indexing, empty and singleton boundaries, traversal, mutable Python lists, immutable strings, insertion and deletion shifts, and operation costs. Searching covers linear and binary search, inclusive interval invariants, sorted input, success and failure, duplicates, and comparison growth. The explanations distinguish Python's dynamic list from arrays or lists in other languages and define the cost model before stating asymptotic bounds.

The lesson `Demonstration` union gained a separate `algorithm` variant and optional additional demonstrations. Existing authored `trace` content and its player remain unchanged. `src/lib/algorithm-steps.ts` generates deterministic steps for traversal, linear search, and binary search from predefined numeric scenarios. React renders those snapshots in `algorithm-visualizer.tsx`; each step owns an array snapshot and highlighted-index list so sorting can reuse the player. It does not execute learner code or infer steps from public test results. Binary search accepts only ascending sorted input. A linear search returns the leftmost duplicate; binary search returns the first matching midpoint encountered. Search bounds are inclusive. The comparison count follows the lesson's reference code: linear search performs one equality test per inspected element; binary search performs equality and, after a mismatch, an ordering test. Counts are operations, not timing measurements.

The player supports previous, next, reset, scenario selection, and optional timed playback. Timers are cleaned up on step changes and unmount; scenario changes pause playback and reset position. Reduced-motion preference disables playback while preserving manual steps. Indexed cells wrap at mobile widths, show text labels for active and boundary states, and current step text is announced as one polite live region. Controls use native buttons and select elements with visible focus styling.

Seven independent Python labs in `src/content/dsa-coding-exercises.ts` cover safe traversal, indexed accumulation, empty access, off-by-one repair, linear search, binary search, and a non-progressing binary boundary. They use the existing disposable Pyodide Worker, public assertions, saved workspaces, cancellation and deadlines. The tests cover empty, singleton, first, last, missing, duplicate, and odd/even interval cases. Public tests are finite practice feedback, not secure grading or proof of mastery. The C++ playground and WASI constraints are untouched.

## Limits and next direction

The visualizer uses small predefined numeric cases so every step can be explained and checked. It does not visualize arbitrary learner code, string comparison costs, or mutation effects yet. Binary search assumes the input was already sorted; sorting cost is outside this lesson's search comparison count. The Python Worker and same-origin public assertions are appropriate for local practice, not hostile-code isolation or credentialed grading. Browser storage remains device-local and can be cleared by the browser. Automated tests verify software behavior and authored examples, not educational effectiveness.

V0.7 can reuse the pure step contract for sorting by emitting changed array snapshots for swaps and writes without a second player. More independently authored transfer tasks and observational learning research would be useful before strengthening diagnosis claims.
