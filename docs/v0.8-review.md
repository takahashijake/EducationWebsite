## Lesson and algorithm contracts

The Sorting lesson states an ascending numeric order contract, distinguishes in-place mutation from returning a copy, and explains why sorting can precede binary search while carrying its own cost. It includes objectives, four conceptual sections, three shared algorithm demonstrations, a same-input comparison, a worked bubble trace, runnable Python examples, misconceptions, takeaways, and three mapped knowledge checks. The lesson recommends Python's `sorted()` and `.sort()` for ordinary work.

`src/lib/algorithm-steps.ts` remains the single entry point for traversal, search, and sorting traces. The three new pure algorithms copy their input and emit complete snapshots. The existing visualizer renders the snapshots with indexed values, text labels, original item positions, operations, sorted regions, and counters. Previous, next, reset, scenario selection, optional playback, and reduced-motion behavior are inherited. The new shared comparison panel reads the final counters from those exact generators, so it cannot drift into an independent statistics implementation. Empty, singleton, sorted, reverse, duplicate, all-equal, signed, and typical inputs are authored as small scenarios. Arbitrary visualizer input over 16 values or containing a non-finite number is rejected.

Counting conventions are explicit:

- One value-ordering test is one comparison. Loop-bound checks and local-variable assignments are excluded.
- One exchange of two distinct indexed positions is one swap and two indexed array writes.
- A shift or final key insertion is one indexed array write. A key held in a temporary variable is not an array write.
- Selection skips self-swaps; insertion skips a redundant key write when no value moved.

Bubble compares adjacent values and swaps only on strict `>`; a completed pass grows the sorted suffix, and a no-swap pass terminates early. Selection scans every remaining suffix with strict `<`, keeps the earliest minimum on ties within a scan, and places it with a non-self exchange. Insertion holds a key, shifts only strictly greater prefix values, and inserts only after a shift. These exact variants have O(1) auxiliary array space and O(n²) average and worst-case time. Optimized bubble and insertion have O(n) best-case time on sorted input; selection still makes `n(n - 1)/2` value comparisons. The operation totals are not measured runtime. Bubble and insertion preserve equal-key identity order; conventional swap-based selection may reorder it. Tests track decorated original identities because equal numeric values alone cannot prove stability.

The visualizer follows authored deterministic algorithms, not learner-submitted Python. The Code Lab executes Python separately in the existing disposable Worker. Its public tests are feedback, not secure grading or evidence of a particular implementation beyond the observed checks.

## Security and limitations

The baseline main commit `6876569` has a failing `Rubber Duck / CodeAnalyzer` status. V0.7's review documents its existing Grade C Worker and repository-owned test findings; that historical inventory is not assumed to be identical to a future PR-head scan. This branch does not change the execution Workers, introduce dynamic evaluation of generated content, or add runtime dependencies. New question generation and visualization use small, bounded arrays and authored templates. The local authoring test launches Python 3 only for repository-authored reference strings and public assertions; the production application does not invoke a server-side Python process. The PR-head scanner status and any new findings must be compared separately after publication; a failing check must remain visible.

The player uses predefined numeric inputs and does not trace arbitrary learner code. The cost model ignores loop-control, allocation, and interpreter overhead, so it cannot rank real-world speed from small displayed counts. Browser-local evidence can be lost or denied, and public tests are finite observations, not mastery. Automated tests validate software and authored examples, not educational effectiveness. Human teaching, screen-reader, and cross-browser review remain useful future work.
