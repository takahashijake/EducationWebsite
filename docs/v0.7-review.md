## Question-family contract

`src/content/adaptive-families.ts` owns 13 stable authored families: two each for `comparisons`, `loop-boundaries`, `sequence-boundaries`, `sequence-traversal`, `linear-search`, and `binary-invariants`, plus one sorted-input precondition family. A family declares an ID, revision, one primary skill, published topic and review link, difficulty, and a bounded parameter generator. An instance includes its `adaptive-{family}:r{revision}:s{seed}` identity, prompt, context, three shuffled options, one correct index, a reason for each incorrect option, an explanation, two hints, and a worked intermediate step.

The same family ID, revision, and nonnegative 31-bit integer seed reproduce the same instance. Xorshift32 with a stable family-ID mix supplies local parameters and option order. Generator inputs, answer indices, option uniqueness, and content revisions are checked; malformed values are rejected. Templates vary boundary conditions, empty and singleton input, duplicates, misses, sortedness, interval direction, and loop shape as well as numbers. Generation reads only authored data and does not evaluate generated JavaScript or learner code. The evaluator regenerates the canonical instance before accepting an answer.

## Selection and remediation

`src/lib/adaptive-selection.ts` reuses V0.5 `diagnose` and `recommend`, preserving their due-review schedule and priority semantics. Focused misses and combined-miss clues precede due reviews, weak prerequisites, and little direct evidence. A combined miss is described as an uncertain clue, not proof of a specific misconception. A currently practiced skill stays in focus when no urgent review supersedes it. The learner can choose any supported skill. Within a skill the selector prefers a different authored family and an unseen seed from a bounded search; exhausted recent variants fall back deterministically. Time, seed, evidence, and recent history are explicit inputs. A success can open a dependent or prerequisite skill through an optional related-concept action.

The interface offers a conceptual hint and a further reasoning step before submission. After a wrong answer it shows the chosen and correct options, an authored note for the chosen distractor, the actual reasoning, a worked step, a lesson link, and a prerequisite link. It offers a fresh related variation or a next recommended problem. The five-question summary reports independent correct, assisted correct, incorrect, and hint-use counts without a mastery percentage. Native radio controls, fieldsets, keyboard buttons, feedback focus, visible focus styles, a polite status, and wrapping/mobile layout support access without animation.

## Evidence compatibility and local state

Each family is appended to the existing activity catalog as one revision-1, single-skill `retrieval` activity. The unchanged `cs-fundamentals:evidence:v1` record remains `{attemptId, activityId, source, correct, at, revision}`. A parameterized variant shares its family's activity ID, so many variants cannot satisfy V0.5's distinct-activity requirement alone. The first independent correct submission records positive evidence; an initial incorrect submission records negative evidence. Correct work after a hint is counted only in the local session and does not create positive V1 evidence. A submitted instance is counted once, and subsequent variation requests create new instances. Reading, project, Python, C++, and fixed retrieval records keep their previous meanings.

Recent instance identities, the five-question counters, and a bounded presentation counter live in `cs-fundamentals:adaptive-session:v1`, separate from V1 evidence. Its parser caps serialized size and list lengths, rejects unknown family IDs and revisions, and validates the session tally. It does not write during hydration. The client hook follows existing same-tab and cross-tab events and provides a session-only fallback when storage is denied. No name, source code, or personal profile is saved in this store.

## Limits and next direction

Deterministic adaptive practice selects from authored bounded templates; it is not LLM-generated tutoring. A selected distractor has an authored explanation but does not prove what the learner believed. Browser-local answers and public tests are finite practice observations, not comprehensive mastery or secure grading. The five-question policy and due schedule are design choices, not scientifically validated learning outcomes. Local state can be cleared, denied, or affected by a mis-set device clock. Independent human teaching and accessibility review remains valuable.

Sorting can reuse the existing algorithm-step contract in a later curriculum milestone. Additional independently authored families and transfer tasks can extend adaptive coverage without altering V1 evidence semantics.
