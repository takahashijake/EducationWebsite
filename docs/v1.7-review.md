# V1.7 implementation review

## Baseline and audit problems

Starting `origin/main`: `208e95cbed7ae7616c2856d8457baa8bab531af3` (V1.6, committed 2026-10-30T18:35:05-07:00). The October competitive audit found a gap between immediate authored misconception feedback and later skill-level recommendations, scattered next-step navigation, and planned-topic previews that could route learners back to an unrelated lesson.

## Implemented scope

- One vertical slice for the published `comparisons` skill. Two `comparison-policy` distractors have stable authored IDs, explanations, correct rules, boundary contrasts, and a published lesson link. The equality-only distractor remains unlabeled because one answer does not uniquely identify reasoning.
- After a supported wrong independent answer, adaptive practice presents a possible explanation and a different-family `comparison-branch` check at the equality boundary. A correct independent follow-up is counterevidence, not proof that the earlier thought disappeared. Hints continue to prevent independent positive evidence. After the check, the existing recommendation engine suggests a next activity with its reason.
- A separate `cs-fundamentals:misconceptions:v1` record stores bounded, validated signals with activity, instance, selected choice, shared evidence attempt ID, timestamp, catalog revision, and optional independent counterevidence. Existing `cs-fundamentals:evidence:v1`, adaptive session, progress, skill and activity IDs remain unchanged. Invalid/stale records are ignored; denied storage keeps the signal in the tab.
- Learning Insights prioritizes the latest unresolved possible signal, shows its source activity and any later counterevidence, and offers one primary action. Clearing evidence also clears the companion record. Lesson checks give one contextual next action from existing recommendations or a published curriculum fallback. Planned cards say “preview only”; planned pages choose a published prerequisite or same-section lesson before a generic first lesson.

## Architecture and educational safeguards

`src/content/misconceptions.ts` owns authored content; `src/lib/misconception-signals.ts` owns pure validation/transitions; `use-misconception-signals.ts` owns browser storage; existing adaptive selection generates the follow-up with an excluded family. No backend, account, AI service, telemetry, new dependency, code execution surface or Worker permission was added. The authoring rubric is in `docs/misconception-authoring-rubric.md`.

The selected option supports only **a possible** interpretation. Signals are not mastery evidence. A different correct independent answer supplies limited counterevidence; assisted answers and reading do not. Existing scheduled-review logic is unchanged.

## UX and accessibility

Desktop and mobile Chromium journeys passed, including keyboard activation of the recovery check; human assistive-technology review remains necessary.

## Known limits and remaining audit findings

Only one skill and two distinguishable options are mapped. A follow-up after the fifth answer starts a fresh five-question session. Browser-local storage is not portable. The UI does not trace arbitrary learner code; public coding checks are still formative. A live JupyterHub proxy has not been tested. Most importantly, automated tests establish deterministic behavior, **not improved learning outcomes**; educator review and learner studies are required.

The remaining audit findings and release order are in `docs/competitive-audit-implementation-roadmap.md`. **Recommended V1.8:** one unified predict → explain → implement → transfer activity for a graph or DP invariant, with a delayed novel-case evaluation.
