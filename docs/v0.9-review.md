# V0.9 review: Linked Lists and reference reasoning

## Scope and contracts

The existing `linked-lists` topic ID and `/lessons/linked-lists` slug are now published. Advisory prerequisites are Arrays and Strings and Big O. The lesson uses the existing `Lesson` contract, `LessonDemonstration` union, practice components, Pyodide Code Lab, retrieval catalog, evidence V1 store, and adaptive selection. There is no new executor or storage key. The application version is 0.9.0.

`src/lib/linked-list-steps.ts` defines a pure, bounded snapshot generator. Each `LinkedStep` has immutable snapshot copies of nodes `{ id, value, next }`, `head`, `current`, `previous`, `reachable`, `detached`, `operation`, and `explanation`. IDs are logical identities and remain stable after link changes. Every non-null reference must name an existing node. `linkedReachability` follows `next` from `head` and rejects duplicate IDs, dangling references, and cycles. Detached nodes remain in a snapshot to make removal and insertion order visible. A maximum of twelve starting nodes keeps steps finite. The UI orders reachable nodes by links, then detached nodes; its position is not a heap address or actual memory layout. The visualizer follows authored operations only.

Prepend links `new.next` to the old head before moving head. Append scans to a null next link when only head exists, then attaches one fresh node. First-match deletion updates head at position zero or sets `previous.next` to `current.next` elsewhere. The remaining reachable identities are preserved. Empty and singleton cases and duplicate values are explicit scenarios.

## Python exercise contract

Every lab supplies `class Node` with `value` and `next`, defaulting `next` to `None`. `collect_values(head)` returns a new value list. `find_first(head, target)` returns the exact first matching node or `None`. `prepend(head, value)` returns a fresh head with the old head as its next. `append(head, value)` returns the original head for a nonempty list or the fresh singleton for empty input. `remove_first(head, target)` returns the possibly updated head after bypassing only the first match. Tests assert object identity, order, null termination, unchanged links where required, and preservation of unaffected nodes. Each starter intentionally fails meaningful checks. An authored reference appears in a collapsed disclosure after a learner runs public checks. Revealing a hint or that reference suppresses independent positive concept evidence for passing checks in the current visit. Authored solutions are executed with local Python in the test suite; learner code runs only in the existing disposable browser Worker with its existing deadline, source, output, and input limits.

## Learning integration

Permanent skills: `linked-node-identity`, `linked-traversal`, `linked-head-insertion`, `linked-deletion`, `linked-complexity`, and `linked-aliasing`. Each has a published lesson destination, advisory skill prerequisites, two authored focused retrieval questions, and at least one adaptive family. Three lesson checks and five Python activities map to the relevant skills. Ten adaptive families vary chain lengths, values, duplicates, target positions, empty heads, tail availability, and link rewiring. The existing seeded generator, next-question selection, remediation, hint handling, and V1 evidence rules apply. Reading completion and hints do not create positive evidence; passing public Python checks is limited local evidence.

## Accessibility and security

The player uses a native scenario select and buttons for previous, next, and reset; it has visible keyboard focus, text labels for every node and next reference, narrated reference transitions in a polite live region, and a wrapping mobile layout. Reduced-motion CSS removes animation and transitions. Text and border styles distinguish reachable from detached nodes without relying only on color. Browser and screen-reader behavior needs further human review.

No new server-side code execution, hosted inference, unsafe HTML interpretation, or runtime package was added. Adaptive questions come from bounded authored templates. The reference engine rejects invalid or oversized input and cycles in its reachability helper. Pyodide remains an educational browser Worker, not a strong hostile-code sandbox; public checks do not certify correctness or mastery. Any scanner findings should be compared with the V0.8 documented Rubber Duck / CodeAnalyzer baseline before being classified as new defects.

## Remaining limits and V1.0 direction

The visualizer traces only its authored algorithms and uses logical labels instead of memory addresses. It has no free-form pointer editor or arbitrary learner-code tracing. Public Python cases are visible and bounded, so learners can pass them without a general solution. V1.0 could connect these reference ideas to Stacks and Queues, add independent transfer tasks, and arrange human accessibility and learning-effectiveness review.
